Compilers · Pointer / alias analysis

One of the hardest static-analysis problems: deciding what each pointer may refer to. Almost every other analysis — constant propagation, dead-code elimination, escape and side-effect analysis, call-graph construction, bug finding — is only as precise as the points-to sets it is handed. The reading path here starts with Hind's survey to fix the design dimensions (flow-, context-, field-, object-sensitivity), then the two foundational algorithms and the precision spectrum between them (Andersen's inclusion vs. Steensgaard's unification), the flow- and context-sensitive tradition for C, the tricks that scale inclusion-based analysis to real programs, the CFL-reachability and demand-driven reframing, the BDD and declarative engines that made whole-program context sensitivity practical, the object- and type-sensitivity that hit the sweet spot for object-oriented code, and finally the frameworks that carry these ideas into LLVM, C/C++, and modern Java.

How to read this list. Read Hind first for the vocabulary — every later paper is a point in the design space he lays out. Then read Andersen and Steensgaard back to back: they are the two poles (precise-but-costly vs. fast-but-coarse) that the rest of the field interpolates between and scales up. After that the sections are roughly independent; pick the axis (scaling, demand-driven, object-sensitivity) you care about.

Framing the problem

Read this first: it names the design dimensions every later paper is a point within.

  1. Pointer Analysis: Haven't We Solved This Problem Yet? — Michael Hind
    PDF·8ppPASTE 2001 · DOI · PDF
    The canonical survey: frames flow-, context-, field-sensitivity and the precision/scalability tradeoffs, and remains the best map of the territory.

The two foundational algorithms

Andersen (subset) vs. Steensgaard (unification) are the two poles; everything else interpolates or scales one of them.

  1. Program Analysis and Specialization for the C Programming Language — Lars Ole Andersen
    PDF·43ppPhD thesis (DIKU) 1994 · PDF
    Origin of "Andersen-style" inclusion (subset-constraint) analysis: the precise-but-cubic baseline.
  2. Points-to Analysis in Almost Linear Time — Bjarne Steensgaard
    PDF·10ppPOPL 1996 · DOI · PDF
    "Steensgaard-style" unification analysis: precision traded for near-linear scale, the other pole.
  3. Fast and Accurate Flow-Insensitive Points-to Analysis — Marc Shapiro, Susan Horwitz
    DOI·12ppPOPL 1997 · DOI
    A tunable family sitting between Andersen and Steensgaard, making the precision/cost dial explicit.
  4. Unification-Based Pointer Analysis with Directional Assignments — Manuvir Das
    PDF·12ppPLDI 2000 · DOI · PDF
    "One-level flow": nearly Steensgaard's speed with much of Andersen's precision — the practical middle ground.

Flow- and context-sensitivity for C

The interprocedural aliasing tradition that first pinned down what "sensitivity" buys you.

  1. A Safe Approximate Algorithm for Interprocedural Pointer Aliasing — William Landi, Barbara Ryder
    DOI·12ppPLDI 1992 · DOI
    The first practical interprocedural may-alias algorithm for C; it set the problem statement the field worked from.
  2. Efficient Flow-Sensitive Interprocedural Computation of Pointer-Induced Aliases and Side Effects — Jong-Deok Choi, Michael Burke, Paul Carini
    DOI·13ppPOPL 1993 · DOI
    The foundational flow-sensitive interprocedural formulation, with the strong/weak-update machinery later work builds on.
  3. Context-Sensitive Interprocedural Points-to Analysis in the Presence of Function Pointers — Maryam Emami, Rakesh Ghiya, Laurie Hendren
    DOI·12ppPLDI 1994 · DOI
    Full context sensitivity for C with an invocation-graph treatment of function pointers — the classic account of on-the-fly call-graph construction.

Scaling inclusion-based analysis

How Andersen-style analysis was made fast enough for millions of lines.

  1. Partial Online Cycle Elimination in Inclusion Constraint Graphs — Manuel Fähndrich, Jeffrey Foster, Zhendong Su, Alexander Aiken
    PDF·11ppPLDI 1998 · DOI · PDF
    Collapsing cycles in the constraint graph — the key idea behind every fast inclusion solver since.
  2. Ultra-fast Aliasing Analysis using CLA (a million lines of C in a second) — Nevin Heintze, Olivier Tardieu
    PDF·10ppPLDI 2001 · DOI · PDF
    Field-based Andersen-style analysis engineered to enormous scale.
  3. The Ant and the Grasshopper: Fast and Accurate Pointer Analysis for Millions of Lines of Code — Ben Hardekopf, Calvin Lin
    PDF·10ppPLDI 2007 · DOI · PDF
    Lazy and hybrid cycle detection: large speedups over Fähndrich et al. with no precision loss.
  4. Flow-Sensitive Pointer Analysis for Millions of Lines of Code — Ben Hardekopf, Calvin Lin
    PDF·10ppCGO 2011 · DOI · PDF
    Sparse, staged flow-sensitive analysis with strong updates — flow sensitivity finally made to scale.

CFL-reachability and demand-driven analysis

Reframe points-to as a graph-reachability problem, then compute only the queries you ask.

  1. Precise Interprocedural Dataflow Analysis via Graph Reachability — Thomas Reps, Susan Horwitz, Mooly Sagiv
    PDF·14ppPOPL 1995 · DOI · PDF
    The IFDS/CFL-reachability framework that reframes context-sensitive interprocedural analysis (and, later, points-to) as language-reachability.
  2. Demand-Driven Points-to Analysis for Java — Manu Sridharan, Denis Gopan, Lexin Shan, Rastislav Bodík
    PDF·18ppOOPSLA 2005 · DOI · PDF
    Points-to as CFL-reachability over a program-expression graph, answering single-variable queries on demand.
  3. Refinement-Based Context-Sensitive Points-to Analysis for Java — Manu Sridharan, Rastislav Bodík
    PDF·17ppPLDI 2006 · DOI · PDF
    Adds client-driven refinement, spending precision (field and call-site matching) only where a query needs it.
  4. Demand-Driven Alias Analysis for C — Xin Zheng, Radu Rugina
    PDF·12ppPOPL 2008 · DOI · PDF
    Carries the CFL-reachability, demand-driven idea back to C, where indirection through the heap makes the language harder.

BDD and declarative engines

Symbolic and relational back-ends that made whole-program context sensitivity tractable.

  1. Points-to Analysis using BDDs — Marc Berndl, Ondřej Lhoták, Feng Qian, Laurie Hendren, Navindra Umanee
    PDF·12ppPLDI 2003 · DOI · PDF
    Represents the enormous points-to relation symbolically with binary decision diagrams — the enabling trick for what follows.
  2. Cloning-Based Context-Sensitive Pointer Alias Analysis Using BDDs — John Whaley, Monica Lam
    PDF·14ppPLDI 2004 · DOI · PDF
    Fully context-sensitive inclusion analysis via call-path cloning, expressed in Datalog and solved with BDDs (bddbddb).
  3. Strictly Declarative Specification of Sophisticated Points-to Analyses — Martin Bravenboer, Yannis Smaragdakis
    DOI·18ppOOPSLA 2009 · DOI
    Doop: whole analyses (including on-the-fly call graphs and exceptions) written as Datalog rules — declarative, and often faster than hand-coded engines.

Context choice for object-oriented programs

For OO code the right kind of context — objects, not call sites — is what makes analysis both precise and affordable.

  1. Scaling Java Points-to Analysis using Spark — Ondřej Lhoták, Laurie Hendren
    PDF·16ppCC 2003 · DOI · PDF
    The open, modular Java points-to framework (in Soot) that made the later OO comparisons reproducible.
  2. Parameterized Object Sensitivity for Points-to Analysis for Java — Ana Milanova, Atanas Rountev, Barbara Ryder
    PDF·41ppACM TOSEM 2005 · DOI · PDF
    Object sensitivity: use receiver objects as context — the dominant precision/scalability sweet spot for OO programs.
  3. Resolving and Exploiting the k-CFA Paradox — Matthew Might, Yannis Smaragdakis, David Van Horn
    PDF·11ppPLDI 2010 · DOI · PDF
    Explains why call-site (k-CFA) context is cheap for functional languages yet ruinous for OO, connecting the functional and pointer-analysis traditions.
  4. Pick Your Contexts Well: Understanding Object-Sensitivity — Yannis Smaragdakis, Martin Bravenboer, Ondřej Lhoták
    PDF·13ppPOPL 2011 · DOI · PDF
    The definitive account of context choice; introduces type sensitivity as a cheaper approximation of object sensitivity.
  5. Hybrid Context-Sensitivity for Points-to Analysis — George Kastrinis, Yannis Smaragdakis
    PDF·11ppPLDI 2013 · DOI · PDF
    Combines call-site and object sensitivity selectively, capturing most of the precision of each at a fraction of the cost.

Inclusion vs. unification, in one sentence. Andersen treats each assignment a = b as a subset constraint (points-to(b) ⊆ points-to(a)) and solves the resulting graph — precise, but the closure is cubic. Steensgaard treats the same assignment as an equality and merges the two objects into one equivalence class — near-linear via union-find, but coarse, because merges are never undone. Every later dimension (flow-, context-, field-, object-sensitivity) is an axis of precision layered on top of that one choice, and most of this list is about buying back precision or scale that the base algorithm gave away.

Key terms

Vocabulary used across this list.

points-to set — the set of abstract objects a pointer may refer to at some program point   may-alias / must-alias — two pointers may alias if some execution makes them point to the same object; they must alias if every execution does   inclusion- (subset-) based — Andersen's model: assignments impose subset constraints between points-to sets; precise but cubic   unification-based — Steensgaard's model: assignments merge objects into one equivalence class via union-find; near-linear but coarse   flow-sensitivity — respecting statement order (a per-program-point solution) instead of one summary for the whole procedure   context-sensitivity — distinguishing a procedure's behavior per caller/context (call-site k-CFA, object sensitivity, or type sensitivity)   field-sensitivity — modeling distinct object fields separately rather than collapsing them   object-sensitivity — using receiver (allocation) objects, not call sites, as the context abstraction — the OO sweet spot   heap abstraction — the finite model of the unbounded heap, usually one abstract object per allocation site   strong vs. weak update — overwriting a points-to set (sound only when the target is a single concrete object) vs. merging into it   CFL-reachability — phrasing an analysis as reachability in a graph under a context-free language of legal paths (the basis of demand-driven analyses)   on-the-fly call graph — building the call graph during the points-to analysis, since resolving indirect calls needs points-to facts and vice versa   soundy — sound except for a few well-understood, deliberately unsound features (reflection, native code) — the honest standard for real analyses
